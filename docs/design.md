# tmdb: the official TMDB plugin

An official Kryspal Media plugin: a metadata provider for TMDB (The Movie Database), implemented with [`github.com/kryspal/plugin-sdk`](https://github.com/kryspal/plugin-sdk) against protocol v1. It declares five capabilities: `metadata.movie`, `metadata.series` (including seasons and episodes), `metadata.person`, `metadata.collection` and `metadata.trailers`; since 2.2.0 also `images.person` (see below).

## Version and releases

The version number is written only in `VERSION`: the program embeds it with `go:embed` as the Manifest version. Releases are built by the CI workflows in `.github/workflows/`: a `v*` tag builds linux/amd64 and linux/arm64 packages and creates a GitHub Release. Any change that alters the binary needs a new `VERSION`; a published version is never changed. `CATALOG.json` holds the display data for the plugin catalog.

## Settings

| Key | Type | Description |
| --- | --- | --- |
| `api_token` | secret, required | The **API Key** (v3, 32 hex digits) or the **API Read Access Token** (v4, starts with `eyJ`) from the API settings page of the TMDB account. Either works: the token is sent as `Authorization: Bearer`; the key can only go in the `api_key` query parameter, so every error message and log masks it |
| `include_adult` | bool | Whether search includes adult content, default false |
| `base_url` | string (advanced) | Default `https://api.themoviedb.org/3`; only for a trusted HTTPS proxy, and it must be https. In regions where `api.themoviedb.org` is unreachable, TMDB's alternate host `https://api.tmdb.org/3` can be used |
| `convert_chinese` | bool (advanced) | Simplified/Traditional conversion in both directions, default true. See "Language" |
| `trim_collection_suffix` | bool (advanced) | Removes a trailing Chinese "series" marker (in full-width or ASCII parentheses) or "Collection" from collection names, default false. Applies to collection data and to the collection name on an item; if nothing is left after trimming, the original name is kept |
| `max_cast` | int (advanced) | Upper limit on the number of cast members, 0 to 500, default 50; 0 means no limit |
| `max_backdrops` | int (advanced) | Upper limit on the number of backdrops (stills), 0 to 200, default 20; 0 means all. For movies, series and collections only the first few backdrops are kept (language preference chain, rating, resolution; the order is not changed); posters and logos are not affected. Reason: TMDB can have hundreds of images for a popular title, the Emby-compatible API puts `BackdropImageTags` in every item response, and too many tags bloat the list responses of clients such as Infuse. The host and the data layer set no limit (whatever the plugin returns is stored) |
| `certification_country` | select (advanced) | Country/region for the certification; the options show country names (not two-letter codes such as TW, F17); the value is a two-letter country code, and `auto` (default) means use the region of the target language, then the US. Two-letter values saved by older versions are still accepted |

`Configure` first decides the kind by format (starting with `eyJ` is a token, 32 hex digits is a key, any other format returns a field error), then validates with `/authentication`: it rejects only when TMDB explicitly returns 401. When TMDB cannot be reached the settings are still accepted; otherwise, if the network is not ready when the server boots, the plugin would stay in "needs configuration" forever. After that, when any call gets a 401 (the token was revoked), the plugin returns `FAILED_PRECONDITION` and waits for the administrator to configure it again.

## TMDB API terms

- **Attribution** (1.4.1; the attribution lives in this plugin and does not appear in core screens; the plugin can be disabled or uninstalled): the notice is the English text TMDB requires, `This product uses the TMDB API but is not endorsed or certified by TMDB.`, identical in every language. It is written only in the Manifest `attribution.text` (shown in the source attribution row of the detail page) and is not repeated in `description` (since 2.0.3; before that the three-language descriptions also ended with this sentence, so the detail page showed it twice); `attribution.link` is the TMDB website. The TMDB logo is obtained from its logos & attribution page and is shown by the plugin detail page.
- **TMDB logo** (1.4.2): `logo/tmdb-primary-short-blue.svg` is the original TMDB official "Primary short (blue)" SVG file (sha256 `8e7b30f7…95f6c`; `TestAttributionLogo` checks it has not been modified). It is embedded with `go:embed` and placed in `attribution.logo_url` as a base64 data URI (so the plugin page does not need to reach TMDB). Source: https://www.themoviedb.org/about/logos-attribution (file `/assets/v4/logos/v2/blue_short-8e7b30f7….svg`, obtained 2026-10-09). Terms of use: https://www.themoviedb.org/api-terms-of-use and the brand guidelines page above; do not change the colors or proportions, it must be less prominent than this product's own logo, and it must not imply TMDB endorsement. The host accepts http/https URLs or base64 SVG/PNG data URIs of at most 32 KiB, and drops everything else.
- **Cache of at most 6 months** (section 1.C): the plugin caches whole-season responses and series titles in memory for 30 minutes only (see "Seasons and episodes"). The server handles this by fetching again after about 5 months.
- **No charging, and no training ML on TMDB content** (section 2.A): this plugin must not be bundled into a paid plan.
- **Rate limiting**: self-limited to 40 requests per second and 12 concurrent (`requestsPerSecond`, `maxConcurrent`; the plugin also declares `SuggestedConcurrency` 12; TMDB's limit is about 50 requests per second, leaving a 20% margin; owner, 2026-10-10: TMDB's limit is not low, so it can be raised. It was 20 per second and 4 concurrent; with 150 ms request latency and 24 concurrent callers, measured throughput rose from about 19.9 to about 39.6 requests per second, `TestThroughputWithLatency`). On 429 it returns `RESOURCE_EXHAUSTED`, with retry-after taken from TMDB's `Retry-After` and 10 seconds when it is missing; the server pauses the whole plugin until then; after the pause it runs at **half the rate** for 60 seconds (`slowdownAfter429`), so it does not jump straight back to the limit and get throttled again (`TestSlowdownAfterRateLimit`). A 5xx or a dropped connection is retried once inside the plugin after waiting 0.5 to 1 second.

## Behavior

See [docs/research.md](docs/research.md) for the design basis and the comparison with other products.

### Aliases and prefixes in search scoring (1.3.2, prefix direction in 1.3.3)

Candidates for a name search are scored by the plugin itself (`titleScore`): identical 1; prefix depends on direction: when the candidate has extra text beyond the query (a sequel number, a subtitle) **0.85** (0.15 below identical, so the runner-up is not so close that the result is judged uncertain), and when the query has extra text beyond the candidate (the directory name carries a foreign-language name or a note, and the candidate is a prefix of the query) **0.95** (1.3.3: the score from before 1.3.2 is kept, and still passes the host's 0.9 threshold); contains 0.8; all words present 0.6; otherwise at most 0.5 by bigram similarity. TMDB's search matches aliases and per-language translations, but the results return only the localized title and the original title, so a first result that was the answer could still score 0. Now: when the best score is below `goodMatch` (0.8) (after retrying with the other Chinese script), one request `/{movie|tv}/{id}?append_to_response=alternative_titles,translations` is made for each of the **top 3** candidates, and the aliases and per-language translations are compared too, taking the highest score; the year and missing-poster deductions are unchanged. Entries that already matched cost no extra requests; the aliases and translations of the same ID are cached for 30 minutes (at most 512 entries, with concurrent requests merged by single-flight), and when they cannot be fetched they are skipped without affecting the search. Tests (synthetic titles): `TestSearchUsesAliases`, `TestSearchUsesTranslations`, `TestSearchSkipsAliasesWhenMatched`, `TestPrefixScoreGap`, `TestPrefixScoreDirection`. Directory names mixing Chinese and English with noise (for example "<Chinese name> Original Name <Chinese subtitle tag>", whose whole string scores at most 0.85/0.80) are left to name normalization in P3.

### Hint search for name recognition (2.1.0)

It declares `metadata.series.absolute`; it also declares `metadata.search.hints` (2.1.5). 2.1.2 had suspended that declaration (a first evaluation scored phase-2 movies 4/68; the cause was artifacts of the evaluation tool and gaps in the replay cache, not the plugin); a later measurement (replay with 0 misses) put phase 2 at 97/101 with 0 wrong applications, which passes the gate, so it is declared by default. When a `SearchRequest` carries hints (`titles` is non-empty) it goes through `hints.go`; a request without hints goes through the single-title search as before (see "Aliases and prefixes in search scoring" above), and its behavior is unchanged.

- **Query plan** (stops at the first match: best score >= 0.9; one Search makes at most 10 name searches and detail requests in total, ID lookups not counted, cache hits not counted): (1) the first title (`name`), with `year` for movies when the year source is a parenthesized or standalone token; (2) if step 1 carried a year and found no match, the same title without the year; (3) the other titles (at most 2, by weight, variants excluded); (4) variants of a Chinese title (titles with `role=VARIANT`; when there are none, the other Chinese script is used as the variant; at most 2); (5) when the best score is < 0.8, or the top few are less than 0.1 apart and there is information that can disambiguate (year, season/episode structure, runtime), the details of the top 3 are fetched (`alternative_titles`, `translations`, plus `release_dates` for movies; the season and episode counts of a series come back with the details).
- **Scoring features**: title (for each hint, the highest across the candidate's localized name, original name, aliases and per-language translations; sequel numbers are normalized so that `Ⅱ`/`II`/the Chinese "part two" form/a trailing Chinese numeral two all mean 2; the segments of a mixed Chinese-English title are compared separately, capped at 0.95; variants capped at 0.95); year (difference 0 no deduction, 1 year -0.03, 2 years -0.06 when the title is identical or an alias matches and otherwise -0.15, 3 or more years -0.3; a release year in any country equal to the local year counts as difference 0; when the year source is inferred from context the deduction is halved; source NONE no deduction); shape (series: +0.03 when the local season/episode layout fits, -0.1 on a clear mismatch; a run of consecutive episodes in one season that fits the whole series also counts as fitting); anime flag (+0.02 with the animation genre, -0.05 without); original language or production country matching the hint +0.03 (no data, no deduction); runtime (movies: within 10% +0.03, over 30% -0.05); missing poster -0.01; the sequel guard for movies is the same as in the single-title search; ties are ordered by popularity (no bonus). Scores are clamped to 0 to 1.
- **Response**: `matched_title` is the name that matched (the candidate's localized name, original name, alias or translation), and `reasons` are reason codes (`title.exact`/`alias`/`prefix`/`partial`/`weak`, `title.variant_cap`, `year.exact`/`diff1`/`diff2`/`far`/`release_date`/`missing`/`unknown`, `shape.ok`/`mismatch`, `genre.anime`/`not_anime`, `language.match`/`region.match`, `runtime.ok`/`off`, `sequel.cap`, `sequel.exempt`, `year.twin`). Edition words (`formatwords.go`, 2.1.7): when a title becomes identical only after removing a theatrical-edition marker (the Simplified and Traditional Chinese "theatrical version" and "movie version" markers, the Korean equivalent, or "The Movie"), the score is capped at the identical-title cap of 0.95 (`editionCap`, reason code `title.variant_cap`); words that denote a different work, such as the Chinese "recap compilation" marker, are not removed, and a title shorter than 3 characters after stripping is not stripped. Same-title rival (`year.twin`): when the same result list holds a candidate whose title is identical and whose year matches exactly, the candidate whose title is identical but whose year is 1 to 2 years off is deducted a further 0.06 (two works with the same name two years apart can be told apart only by year, and a 0.06 gap is not enough for the first to lead by 0.1); with only one such candidate, or no rival whose year matches exactly, nothing changes. Exception to the sequel guard (`sequel.exempt`): when the matched title is itself identical (not one capped by the variant cap) and the year matches exactly, and that title has no sequence number (the number is only in another title, for example a Chinese title with the sequel number 2 paired with the English title "Top Gun Maverick"), the guard does not cap; when the year is unknown or does not match, the guard applies as before.
- **Cache** (within the terms' 6-month limit, 30 minutes in memory): search results (kind, language, adult setting, year, query string) and candidate details (kind, ID). Rate limiting reuses the plugin's self-limit (40 per second, 12 concurrent; the 20 per second written in  was superseded by the owner's decision of 2026-10-10).
- **Failure**: if the first query fails an error is returned; if a later query or detail request fails it is skipped and the results already obtained are used; rate limiting and token invalidation are passed up as usual.
- **Absolute episode number**: when `GetItem(EPISODE)` carries `absolute_episode_number` and no season/episode, the plugin accumulates the episode counts of the series' seasons (from season 1, specials excluded) to map back to (season, episode), then fetches that episode; beyond the whole series it returns NOT_FOUND. The season/episode counts of a series come from the detail cache above, so a series is requested only once.
- Tests (`hints_test.go`, synthetic titles, fake TMDB server; the stop condition of the query plan and the shape deduction were verified by mutation): stopping at the first matching query, the year parameter, the query plan and the request limit, alias and detail caches, the year grading table, sequel normalization and mixed Chinese-English titles and the variant cap, each scoring feature, popularity ordering and the unchanged legacy path, failure and rate limiting, absolute episode numbers, capability declaration.

### Rating source (2.1.1)

`ItemMetadata.ratings` gets one entry `{source: tmdb, value: vote_average, max: 10, votes: vote_count}` (movies, series, episodes; not given when there is no score); `community_rating` is still filled with the same score. TMDB does not provide IMDb ratings, so this is the only entry (sources such as IMDb and Douban need another plugin).

### Interface language (1.3.1)

The settings form and error messages are localized according to the language the host passes in `Describe`/`Configure`; the string table is in `messages.go` (`github.com/kryspal/plugin-sdk/i18n`): en, zh-TW and zh-CN; the fallback chains are zh-CN -> zh-TW -> en and zh-TW -> zh-CN -> en, and other languages and the empty string fall back to English. The Simplified strings were generated with OpenCC `tw2sp` and then proofread by hand (terms for token, key, account and so on). `TestDescribeLanguages` checks that the English contains no Han characters, that zh-TW is Traditional and zh-CN is Simplified (including field error messages); `TestMessagesComplete` checks that the keys are complete. The attribution (`attribution.text`) is the English text required by the TMDB terms, identical in every language. When adding text, all three languages must be filled in.

### Language

Metadata is stored once, scraped in the language of the library, so what the plugin returns is already the result in the target language.

- **Language codes**: BCP 47 converted to TMDB's "language-region". `zh-Hant` becomes `zh-TW`, `zh-Hans` and a bare `zh` become `zh-CN` (TMDB treats `zh` as Simplified); when there is a region the region decides, for example `zh-Hant-HK` becomes `zh-HK`.
- **Fallback chain**: target language -> (Chinese) the other Chinese regions -> the requested fallback language -> en-US, de-duplicated.
  - zh-TW: TW -> HK -> MO -> CN -> SG
  - zh-HK, zh-MO: HK -> MO -> TW -> CN -> SG
  - zh-CN, zh-SG: CN -> SG -> TW -> HK
- **Deciding whether a translation exists**: when TMDB lacks a translation, `title`/`name` return the original text and the episode name returns a placeholder, so the value for that language in `translations` is always what is checked. The Chinese ordinal placeholders (the "Episode N" form with the counters for episode, chapter, season, round or part), "Episode N", "Season N" and bare digits count as placeholders, equivalent to missing.
- **Title**: the translation in the target language -> (Chinese) the Chinese alias for the target region (`alternative_titles`; Taiwan titles are often registered only there) -> when the original text is in the target language, the original title -> translations in the other languages of the fallback chain -> the original title.
- **Overview, tagline, collection name**: the first non-empty one along the fallback chain.
- **Simplified/Traditional conversion**: when what was obtained is in the other Chinese script, it is converted to the target script with OpenCC and regional wording is applied. Simplified to Traditional: target TW uses `s2twp`, HK/MO use `s2hk`; Traditional to Simplified: source TW uses `tw2sp`, HK/MO use `hk2s`. When the setting `convert_chinese` is false nothing is converted and the text is used as is.
- **Genres**: looked up by genre ID in the plugin's own name table (`genres.go`; en, zh-CN, zh-TW; zh-HK/MO use zh-TW and zh-SG uses zh-CN). When the table has no entry, TMDB's name is used, converted to the target script for Chinese. Adding a language only needs one more column in the table.
- **Person names**: the translation in the same language (those from other regions converted to the target script) -> (Chinese) a Chinese alias in `also_known_as`: the script is first judged by conversion, an alias confirmed to be in the target script takes priority, one written the same in both scripts comes next, and one in the other script is used after conversion; aliases mixed with kana or hangul are skipped -> TMDB's main name. Translations in other languages are not used.
- **Season name**: a season name is used only when it is in the same language, is not a placeholder, and does not equal the series title in any language (TMDB has data where the series title is filled in as the season name); otherwise it is generated according to the target language: the Chinese "Season N" and "Specials" (zh-CN uses the Simplified characters for "Specials"), "Season N" and "Specials".
- **Episode name**: when the target language's name is a placeholder or missing (for a Chinese target it must also contain Han characters), the whole season in each language along the fallback chain is fetched to fill it in, converted to the target script; when every one is a placeholder the name is left empty, and the server or client shows "Episode N".

### Search

- Only movies and series are accepted.
- ID hints: `tmdb` is used directly; `imdb` and `tvdb` are located with `/find`. On a hit the score is 1 and no name search is made.
- Name search: movies carry `year` (TMDB uses it only for ordering); series do not carry `first_air_date_year` (it filters out results that are one year off).
- The plugin scores by itself (`SearchCandidate.score`, 0 to 1), candidates are in descending score order with ties keeping TMDB's order, and then `limit` is applied:
  - Normalization: NFKC (full-width to half-width), lowercase, Chinese unified to Simplified, keeping only letters and digits.
  - Title score is the higher of the translated title and the original title: identical 1, prefix 0.95, contains 0.8, every word of the query present 0.6, otherwise the Dice coefficient of character bigrams times 0.5.
  - Year: same no deduction, one year off -0.05, more than that -0.2, candidate has no date -0.1; no poster -0.01.
- When the best score of a Chinese query is below 0.8, the search is made once more in the other script (a Traditional query converted to Simplified, and the reverse) and the results are merged. TMDB's zh-CN translations and aliases are the most complete.

### GetItem

- **Airing status** (`status`, series only): Returning Series, In Production, Planned and Pilot are ongoing; Ended and Canceled are finished; anything else is left empty.
- **Actual language** (`language`): the language the result actually uses. When the title comes from a translation in the target language, an alias for the target region, or the original text is already in the target language, it is the target language; Chinese taken from the other script and converted counts as the target language (with conversion off it is the source language); when it falls back to another language of the fallback chain it is that language (for example `en-US`); when it falls back to the original title it is TMDB's `original_language` (two letters, for example `ja`). When a season name comes from a translation it follows the rules above, and a generated season name is in the target language; for an episode it follows the episode name, and the overview when there is no episode name.
- **Trailers** (`trailers`): `videos` is appended, and `include_video_language` carries the languages of the fallback chain plus `null`; only YouTube Trailers and Teasers are taken, ordered by: language (target language plus target region -> the order of the fallback chain -> no language tag -> others), Trailer before Teaser, official first, more recently published first; the same video is de-duplicated, with at most 5. The URL is `https://www.youtube.com/watch?v=<key>`.

- **Movies and series**: one request appends `translations`, `alternative_titles`, `images` and `external_ids`; movies also get `credits` and `release_dates`, and series also get `aggregate_credits` (the `credits` of `/tv/{id}` has only the cast of the latest season) and `content_ratings`. The end date of a series is filled in only when `status` is Ended or Canceled.
- **Seasons and episodes**: taken from the whole-season response `/tv/{id}/season/{n}`; the target-language request appends `images`, `translations` and `credits`, and fallback languages fetch only episode names and overviews. The whole-season response is cached in memory by (series, season, language) for 30 minutes, at most 64 entries, concurrent requests with the same key are merged into one, and errors are not cached. Refreshing a 20-episode season drops from 20 to 40 requests to one request per language used by the fallback chain. The series title needed to judge season names (`/tv/{id}/translations`) is cached the same way.
- **Certification**: the certification country/region is the setting value, otherwise the region of the target language, otherwise the US; when that country has no certification the US one is taken. For movies the first one with a certification is chosen in the release type priority theatrical (3) -> digital (4) -> physical (5) -> TV (6) -> premiere (1) -> limited (2); for series `content_ratings` is used.
- **Cast and crew**:
  - Cast: for series in descending order of episode appearances, with the role taken from the one with the most appearances; for movies TMDB's order. At most `max_cast` people.
  - Episodes: the crew of that episode plus guest stars (de-duplicated, with consecutive order numbers); the cast of the whole series is not poured in.
  - Crew: director, writers (Writing department), producers (at most 5) and composer, de-duplicated by "person, job"; other jobs are skipped.
  - Gender (1.4.0): cast, crew and guest stars all carry TMDB's `gender` (0 unknown, 1 female, 2 male, 3 non-binary) into `Credit.gender`, with no extra requests; unrecognized numbers count as unknown.
- **Person photos** (`GetImages(ITEM_TYPE_PERSON)`, capability `images.person`, 2.2.0; free): all the profile photos TMDB has for a person (`GET /person/{id}/images`), best first (rating, then resolution; SVG skipped), found by the `tmdb` entry of `provider_ids` only. A request that has only a name or an IMDb ID returns an empty list instead of guessing (a wrong match would put someone else's face on a person; the host's `SearchPerson` is for finding the ID); an unknown person is an empty list too; `limit_per_type` caps the count. Any other `type` is `INVALID_ARGUMENT`: movie and series images still come with `GetItem`. In the host's global "person image sources" list it sits next to third-party photo plugins, so an administrator can order "photo library first, then TMDB". The default (empty list) is unchanged: only the data source's own photos (`GetPerson` still returns the profile photos).
- **Person lookup by name** (`SearchPerson`, capability `metadata.person.search`, 1.4.0): for people without a TMDB ID (for example an actor in an NFO that has only a name). It queries `/search/person` by name and, when the name finds nothing, by the first alias; those whose name is identical come first. **`confirmed` is set only when confirmed by works**: the person's `known_for` or `/person/{id}/combined_credits` contains the TMDB movie or series ID in the work hints (movie and series IDs overlap, so the kind must also be the same). When none of the work hints has a TMDB ID, the first work with an IMDb ID is converted to a TMDB ID through `/find`. With no usable work hint no candidate is confirmed and no extra requests are made.
  - Request count: at most 3 per search (search 1 to 2, `/find` 0 to 1, `combined_credits` uses the remaining budget, and `known_for` already confirmed is not queried again); the single retry the HTTP layer makes on a transient error is not included. At most 5 candidates are returned, carrying only ID, name, gender and avatar; the host fetches the full data with `GetPerson`.
- **Images**: original-size URLs (`https://image.tmdb.org/t/p/original…`), downloaded and thumbnailed by the server. The main image of an episode is the still.

### Image order

The protocol requires the first image of each kind to be the preferred one. `include_image_language` carries the languages on the fallback chain plus `xx` and `null`; `xx` and null both mean no text. The region of TMDB images (`iso_3166_1`) is often wrong, so it is used only for ordering and never for filtering.

- Posters and logos: target language plus target region -> target language plus a region of the same script -> target language without a region -> other regions of the target language -> other languages on the fallback chain -> no text -> others. For example zh-TW: zh-TW -> zh-HK, zh-MO -> zh -> zh-CN, zh-SG -> en -> no text -> others. Logos accept only PNG and skip SVG (most clients do not support it).
- Backdrops: those without text first, the rest as above.
- Within the same rank, by rating and then by descending resolution. SVG is skipped.
- `Image.language` is filled with BCP 47: in the `zh-TW` form when there is a region, and an empty string when there is no text.

### Other

- **Provider IDs**: `tmdb`, `imdb`, `tvdb` (series), `wikidata` (people). A person's links include tmdb, imdb, social accounts and personal websites.
- **Errors**:
  - 404 returns `NOT_FOUND`; insufficient parameters return `INVALID_ARGUMENT`.
  - A connection failure, a 5xx (still failing after the retry) or a malformed response returns `UNAVAILABLE`, and the server retries later.
  - Error messages contain neither the token nor the full URL.

## Tests

`tmdb_test.go` tests against a fake TMDB (HTTPS):

- Settings: missing token, wrong token, non-https URL, still accepted when TMDB is unreachable; `max_cast` and `max_backdrops` (default 20, 0 for all, 5, more than the number of images, invalid values and the three-language fields), the range and format of `certification_country`, and `convert_chinese` and `trim_collection_suffix` taking effect.

## Official builds and releases

This repository is the source code of the official Kryspal Media `tmdb` plugin. Official versions are built by this repository's GitHub Actions workflow from a `v*` tag, attached to a GitHub Release, and then added to the Kryspal Media plugin catalog, which Kryspal signs. The Kryspal Media server installs and updates official plugins from that signed catalog and verifies the signature.

A binary you build from this source yourself is **not** signed by Kryspal and is not part of the official catalog. You are free to build, modify and run it under the Apache License 2.0, but the server treats it as a third-party plugin.

Release process (maintainers): update `VERSION` and `CHANGELOG.md` for any change that alters the binary, wait for the CI workflow to pass on `main`, then push an annotated tag `vX.Y.Z` that matches `VERSION`. The release workflow builds linux/amd64 and linux/arm64 packages, creates the GitHub Release and notifies the main repository, which verifies the packages and publishes the catalog. A published version is never changed.
